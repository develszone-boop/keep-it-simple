## 3. Why trikalnetra.com still shows the README

I checked the live domain just now. The response headers say the page was generated by **Jekyll** (`<meta name="generator" content="Jekyll v3.10.0">`, Jekyll SEO tag in the head), and it was last built at 04:31 UTC today.

That is conclusive: GitHub Pages is still publishing through its **built-in Jekyll branch build**, not the artifact our GitHub Actions workflow uploads. Jekyll finds no site config, so it renders `README.md` as the whole site. Nothing in this repository's code can override that — the publishing source is a repository setting.

### What needs to happen on GitHub (only you can do this)

1. Repo → **Settings → Pages → Build and deployment**. Set **Source** to **GitHub Actions**. If it already reads "GitHub Actions", switch it to "Deploy from a branch", save, then switch it back to "GitHub Actions" and save — that clears a stuck legacy Jekyll deployment.
2. Repo → **Actions** tab. Look for a workflow named **pages-build-deployment** (GitHub's automatic Jekyll builder). If any run is queued or in progress, cancel it. Its presence confirms the branch-based source is still active.
3. Open the **Deploy to GitHub Pages** workflow and run it via **Run workflow** (workflow_dispatch is already enabled).
4. When it finishes, the **deploy** job's summary shows the published URL. Reload trikalnetra.com with a hard refresh (Pages caches for 10 minutes).
